# Android OpenGL ES 着色器代码编写指南

本文以本项目常用的 **OpenGL ES 2.0 / GLSL ES 1.00** 为主线，介绍怎样从零编写顶点着色器和片元着色器，以及如何在 Android 中编译、传参和绘制。最后说明 OpenGL ES 3.0 / GLSL ES 3.00 的主要语法差异。项目中的 `day02`、`day05`、`day07` 和 `gles` 示例可以与本文对照阅读。

> 本文讨论的是运行在 GPU 上的 GLSL ES 代码。`GLES20`、`GLES30` 是 Android 提供的 OpenGL ES 调用接口，二者不是 GLSL 语法版本的开关。使用 ES 3.0 语言特性，需要先取得 ES 3.0 上下文，并在着色器源码中声明 `#version 300 es`。

## 1. 渲染管线与两类着色器

一次常见绘制可以理解为：

```text
顶点数据 → 顶点着色器 → 图元装配/裁剪/光栅化 → 片元着色器 → 颜色缓冲区
              ↑                    插值                 ↑
         attribute/uniform        varying         uniform/纹理
```

- **顶点着色器**对每个输入顶点运行一次。它至少需要写出 `gl_Position`，即齐次裁剪空间中的位置；通常也向片元阶段传递颜色、纹理坐标等数据。
- **片元着色器**对光栅化产生的片元运行，计算颜色。ES 2.0 的单颜色输出通常写入 `gl_FragColor`。
- **光栅化**在顶点与片元之间发生。顶点着色器写入的 `varying` 通常在图元内部插值，所以只给出几个顶点的颜色，也可以形成渐变。
- **Program** 是已链接的着色器组合；一个普通图形 Program 至少包含一份顶点着色器和一份片元着色器。

着色器只负责 GPU 上的计算，不负责创建窗口、上传顶点、加载 Bitmap 或发起绘制。这些工作由 Android/Kotlin/Java 代码调用 GL API 完成。

## 2. 最小可运行的 GLSL ES 1.00 示例

下面一对着色器绘制带插值颜色的几何图形。属性名以 `a` 开头，uniform 以 `u` 开头，阶段间变量以 `v` 开头；这只是便于阅读的命名约定。

**顶点着色器：**

```glsl
attribute vec4 aPosition;
attribute vec4 aColor;
uniform mat4 uMvpMatrix;
varying mediump vec4 vColor;

void main() {
    gl_Position = uMvpMatrix * aPosition;
    vColor = aColor;
}
```

**片元着色器：**

```glsl
precision mediump float;
varying mediump vec4 vColor;

void main() {
    gl_FragColor = vColor;
}
```

读这段代码时注意：

1. 两个阶段都有 `void main()`，GPU 以它作为入口。
2. 顶点输入 `aPosition`/`aColor` 由 CPU 侧的顶点属性数组提供；`uMvpMatrix` 由 `glUniformMatrix4fv()` 提供。
3. 顶点与片元中的 `vColor` 必须按接口要求匹配类型与名称。顶点阶段赋值，片元阶段读取。
4. 片元阶段显式声明 `precision mediump float;`。在 GLSL ES 1.00 中，片元 `float` 没有默认精度，不能假定所有设备都接受省略写法。
5. 该例若不对 `aPosition` 做矩阵变换，也可以直接写 `gl_Position = aPosition;`。

## 3. 语法、类型与变量

### 3.1 基本语法

GLSL ES 语法类似 C：语句以分号结束，代码块用花括号包围，大小写敏感，`//` 和 `/* ... */` 是注释。源码可以放在 Kotlin 三引号字符串、Java 字符串，或应用资源文件中；最终传给 `glShaderSource()` 的是源代码字符串。

```glsl
#define SATURATION 0.8

precision mediump float;
uniform float uAmount;

float adjust(float value) {
    // 将结果限制到 0～1
    return clamp(value * SATURATION * uAmount, 0.0, 1.0);
}

void main() {
    float result = adjust(0.7);
    gl_FragColor = vec4(result, result, result, 1.0);
}
```

`#define` 用于预处理常量或条件编译；`#ifdef`/`#endif` 也可使用。需要版本声明时，`#version` 必须在源码开头，之前只能出现允许的空白或注释。扩展功能应以 `#extension 扩展名 : require` 等指令显式开启，并在使用扩展类型或函数之前声明。

### 3.2 标量、向量、矩阵与采样器

| 类别 | 常见 GLSL ES 1.00 类型 | 用途 |
|---|---|---|
| 标量 | `float`、`int`、`bool` | 数值、索引、条件 |
| 向量 | `vec2`/`vec3`/`vec4`、`ivec*`、`bvec*` | 坐标、颜色、法线、布尔分量 |
| 方阵 | `mat2`、`mat3`、`mat4` | 二维/三维变换 |
| 采样器 | `sampler2D`、`samplerCube` | 通过纹理单元读取纹理 |
| 聚合 | 数组、`struct` | 一组同类型值或自定义记录 |

ES 3.00 还提供 `uint`/`uvec*`、更多采样器类型和非方阵等能力。不要把 ES 3.00 的类型直接放入 ES 1.00 源码。

向量与矩阵可通过构造函数创建；标量会填充同类目标的所有向量分量，但不要假定不同数值类型可以在所有表达式中隐式互换：

```glsl
precision mediump float;

void main() {
    vec2 uv = vec2(0.25, 0.75);
    vec3 gray = vec3(0.5);
    vec4 rgba = vec4(gray, 1.0);
    float red = rgba.r;
    vec2 xy = rgba.xy;
    rgba.rgb = vec3(uv.x, xy.y, red);
    float twice = 2.0 * red;
    gl_FragColor = vec4(rgba.rgb * twice, rgba.a);
}
```

向量分量可以使用 `.xyzw`、`.rgba` 或 `.stpq` 访问，同一组内可以组合，如 `color.rgb`、`uv.yx`。`mat4 * vec4` 是矩阵乘向量；`vec4 * vec4` 则是逐分量相乘。`2` 是整数常量，`2.0` 是浮点常量，混用类型时最好显式转换或使用匹配的字面量。

### 3.3 控制流、数组和函数

```glsl
uniform float uWeights[3];

float weightedSum(vec3 values) {
    float sum = 0.0;
    for (int i = 0; i < 3; ++i) {
        sum += values[i] * uWeights[i];
    }
    return sum;
}
```

可使用 `if`/`else`、`for`、`while`、`do-while`、`return` 和自定义函数；片元着色器还可用 `discard` 放弃当前片元。**ES 2.0 不强制设备支持 `while`/`do-while`**；为了兼容性，优先使用边界明确的 `for`，让循环次数和小数组大小在编译时确定，并在目标设备上测试。数组索引必须在合法范围内。GLSL ES 不支持 C 指针与递归函数。

### 3.4 精度限定符

`lowp`、`mediump`、`highp` 描述数值精度与范围等级，例如 `precision mediump float;` 或 `highp vec2 position;`。选择精度时遵循“满足需要即可”：颜色与一般 UV 通常可从 `mediump` 开始，涉及大范围坐标、细小偏移或连续计算时评估 `highp`。

ES 2.0 的顶点阶段浮点类型有默认高精度；片元阶段的高精度浮点并非所有 ES 2.0 设备都支持。需要兼容时可在编译期用 `GL_FRAGMENT_PRECISION_HIGH` 判断，也可在 Android 端用 `glGetShaderPrecisionFormat()` 查询。示例：

```glsl
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif
```

精度会影响结果范围、误差与性能，具体实现随设备变化。对纹理采样器及跨阶段接口，保持声明一致有助于减少链接问题。

## 4. 限定符与阶段间数据

| GLSL ES 1.00 | 可出现的阶段 | 由谁写入 | 典型用途 |
|---|---|---|---|
| `attribute` | 顶点 | 顶点属性数组或常量属性 | 每顶点位置、UV、颜色 |
| `uniform` | 顶点、片元 | 当前 Program 的 CPU 端设置 | 矩阵、颜色、时间、采样器 |
| `varying` | 顶点、片元 | 顶点阶段赋值，光栅化插值 | 传给片元的 UV、颜色 |
| `const` | 两者 | 在源码中初始化 | 编译期常量 |

`uniform` 在一次绘制过程中对各着色器调用保持相同值；下一次绘制前可以更新。`varying` 不是由 CPU 直接上传，不能用 `glGetUniformLocation()` 查询。未被实际使用的属性和 uniform 可能在编译/链接后被优化掉，位置查询返回 `-1`。

变量有全局/局部作用域。`attribute`、`uniform`、`varying` 是接口变量，通常在全局声明；局部变量在函数中声明。普通局部变量应先初始化再读取。

## 5. 常用内置变量和函数

### 5.1 内置变量

| 变量 | 阶段 | 说明 |
|---|---|---|
| `gl_Position` | 顶点输出 | 四维齐次裁剪空间位置，通常必须写入 |
| `gl_PointSize` | 顶点输出 | 绘制点图元时的点大小 |
| `gl_FragColor` | ES 1.00 片元输出 | 常见单颜色输出，ES 3.00 改用用户定义的 `out` |
| `gl_FragCoord` | 片元输入 | 窗口坐标，`xy` 以像素相关单位表示 |
| `gl_FrontFacing` | 片元输入 | 当前片元是否来自正面图元 |
| `gl_PointCoord` | 片元输入 | 点图元内部的纹理坐标 |

`gl_FragCoord.xy` 是窗口坐标，不等于归一化 UV。做全屏效果时可用 `gl_FragCoord.xy / uResolution` 归一化，但要注意 viewport、FBO 大小和坐标原点。

### 5.2 常用内置函数

| 类别 | 函数例子 | 常见用途 |
|---|---|---|
| 数学 | `abs`、`floor`、`ceil`、`fract`、`mod`、`pow`、`sqrt` | 数值变换、周期图案 |
| 三角函数 | `sin`、`cos`、`atan` | 旋转、波形 |
| 范围与插值 | `min`、`max`、`clamp`、`mix`、`step`、`smoothstep` | 阈值、过渡、动画 |
| 向量 | `length`、`distance`、`dot`、`cross`、`normalize`、`reflect` | 距离、亮度、法线/光照 |
| 纹理 | ES 1.00 的 `texture2D`、`textureCube` | 采样二维/立方体纹理 |

例如 `mix(a, b, t)` 表示按 `t` 在线性意义上混合；`smoothstep(edge0, edge1, x)` 产生平滑过渡。`normalize(v)` 输入零长度向量时不要依赖有用结果。`dot` 做灰度时常写为 `dot(rgb, vec3(0.299, 0.587, 0.114))`。偏导函数 `dFdx`、`dFdy`、`fwidth` 在 ES 2.0 需相应扩展支持，在 ES 3.0 是核心语言功能。

## 6. 坐标、矩阵与颜色

### 6.1 位置从模型空间到屏幕

典型顶点变换为：

```glsl
gl_Position = uProjection * uView * uModel * aPosition;
```

`gl_Position` 是裁剪空间坐标 `(x, y, z, w)`。之后 GPU 做裁剪和透视除法，得到归一化设备坐标（NDC）；可见范围通常是 `x/y/z ∈ [-1, 1]`。最后 viewport 把坐标映射到当前渲染目标中的像素区域。

本项目常把 `uProjection * uView * uModel` 预先合并成 `uMvpMatrix`。二维全屏矩形可直接使用 `(-1,-1)` 到 `(1,1)` 的裁剪空间顶点，并设 `w=1`。Android 的 `android.opengl.Matrix` 工具类使用列主序数组表示矩阵；上传到 ES 的 `glUniformMatrix4fv()` 时 `transpose` 应传 `false`。相乘顺序会影响结果，不要交换矩阵和向量。

### 6.2 纹理坐标和颜色

普通二维纹理坐标 `(u, v)` 通常使用 `[0,1]` 范围，超出范围如何处理由纹理的 wrap 参数决定。Android Bitmap、SurfaceTexture、FBO 和显示画面的纵向约定可能不同；上下颠倒时先核对纹理坐标和纹理变换矩阵，而不是随意翻转顶点位置。

`vec4` 颜色常按 `(r,g,b,a)` 表示，示例以 `0.0～1.0` 计算。绘制结果还受混合状态、纹理格式和目标缓冲区影响。若要做严格的色彩处理，还需区分 sRGB/线性空间及预乘 alpha；简单示例的灰度权重只是演示用近似。

## 7. 纹理、滤镜和外部纹理

### 7.1 普通二维纹理

```glsl
precision mediump float;
varying mediump vec2 vTexCoord;
uniform sampler2D uTexture;

void main() {
    gl_FragColor = texture2D(uTexture, vTexCoord);
}
```

`sampler2D` 是采样器 uniform。CPU 侧要先选纹理单元、在该单元绑定 `GL_TEXTURE_2D` 纹理，再把**纹理单元索引**传给采样器，例如 `glUniform1i(uTextureLoc, 0)` 对应 `GL_TEXTURE0`；不能把纹理对象 ID 当成 uniform 值。纹理若没有 mipmap，缩小过滤方式应选择不依赖 mipmap 的模式（如 `GL_LINEAR`），否则可能导致纹理不完整而采样异常。

一个以纹理尺寸为单位移动 1 像素的例子：

```glsl
precision mediump float;
uniform sampler2D uTexture;
uniform vec2 uTexelSize;  // 由 CPU 设置为 (1/宽度, 1/高度)
varying mediump vec2 vTexCoord;

void main() {
    vec3 center = texture2D(uTexture, vTexCoord).rgb;
    vec3 right = texture2D(uTexture, vTexCoord + vec2(uTexelSize.x, 0.0)).rgb;
    gl_FragColor = vec4(abs(center - right), 1.0);
}
```

多次采样可组成模糊、锐化、边缘检测等卷积滤镜；本项目的 `day07/FboRenderer.kt` 给出了 Sobel 边缘检测和 FBO 两遍绘制示例。`uTexelSize` 应使用**被采样纹理**的宽高，不一定是当前屏幕宽高。

### 7.2 SurfaceTexture / Camera / 视频的外部纹理

OpenGL ES 2.0 中常见的 `GL_TEXTURE_EXTERNAL_OES` 纹理需要扩展声明和 `samplerExternalOES`，不能写成普通 `sampler2D`：

```glsl
#extension GL_OES_EGL_image_external : require
precision mediump float;
varying mediump vec2 vTexCoord;
uniform samplerExternalOES uTexture;

void main() {
    gl_FragColor = texture2D(uTexture, vTexCoord);
}
```

CPU 端应把纹理绑定到 `GLES11Ext.GL_TEXTURE_EXTERNAL_OES`，并检查设备扩展支持。`SurfaceTexture.updateTexImage()` 更新图像后，调用 `getTransformMatrix()` 获取最新纹理矩阵；顶点着色器常按 `(uTexMatrix * aTexCoord).xy` 传递校正后的 UV。外部纹理的采样与参数限制不同于普通二维纹理，不能假定两者可以直接替换。项目 `gles/Texture2dProgram.java` 有普通纹理、外部纹理、黑白及卷积四种着色器示例。

## 8. Android 侧的 API 与调用顺序

### 8.1 从源码到 Program

必须在有当前 EGL 上下文的 GL 线程上创建和使用 GL 对象。使用 `GLSurfaceView` 时，通常在 `Renderer.onSurfaceCreated()` 编译/链接，在 `onSurfaceChanged()` 更新 viewport，在 `onDrawFrame()` 设置状态并绘制。

```text
glCreateShader → glShaderSource → glCompileShader → glGetShaderiv(GL_COMPILE_STATUS)
                                                     ↓ 成功
glCreateProgram → glAttachShader(顶点/片元) → glLinkProgram
                                                    ↓
                             glGetProgramiv(GL_LINK_STATUS) → 查询位置
                                                    ↓
                    glUseProgram → 设置 uniform/属性/纹理 → glDrawArrays
```

本项目的 `GlUtil.loadShader()` 和 `GlUtil.createProgram()` 已封装了编译/链接与状态检查。若自己编写工具函数，编译失败查看 `glGetShaderInfoLog()`，链接失败查看 `glGetProgramInfoLog()`；成功链接后，在不再需要单独 Shader 对象时可以 `glDetachShader()`/`glDeleteShader()`，最终不用 Program 时 `glDeleteProgram()`。EGL 上下文丢失或重建后应重新创建相关对象并重新查询位置。

### 8.2 核心 API 速查

| 目标 | Android GLES20 API | 关键点 |
|---|---|---|
| 创建/编译 | `glCreateShader`、`glShaderSource`、`glCompileShader`、`glGetShaderiv` | 查看 `GL_COMPILE_STATUS` 和日志 |
| 链接/使用 | `glCreateProgram`、`glAttachShader`、`glLinkProgram`、`glGetProgramiv`、`glUseProgram` | 查看 `GL_LINK_STATUS`；传参前先使用 Program |
| 查询输入 | `glGetAttribLocation`、`glGetUniformLocation` | 针对已链接的 Program；`-1` 表示没有活动位置 |
| 顶点属性 | `glVertexAttribPointer`、`glEnableVertexAttribArray` | 分量数、数据类型、stride 字节数和 Buffer position 要匹配 |
| 普通参数 | `glUniform1f`、`glUniform2f`、`glUniform4f`、`glUniform1i` | 类型与 Shader 声明匹配；采样器用整数纹理单元索引 |
| 矩阵参数 | `glUniformMatrix4fv` | `count=1`、`transpose=false`、16 个 float |
| 纹理 | `glActiveTexture`、`glBindTexture`、`glTexParameteri`、`glTexImage2D` | 纹理目标与采样器类型匹配 |
| 输出绘制 | `glViewport`、`glClear`、`glDrawArrays`、`glDrawElements` | 顶点数、图元类型和索引范围要匹配 |
| 调试/释放 | `glGetError`、`glDeleteShader`、`glDeleteProgram` | 结合编译/链接日志定位错误 |

`glGetUniformLocation()`/`glGetAttribLocation()` 的 location 属于特定 Program 的一次链接结果，重建或重新链接后要重新查询。`glUniform*()` 修改的是当前 `glUseProgram()` 选中的 Program。顶点属性数组的启用和数据布局也要在绘制前准备好。详细的参数签名、VBO、UBO、实例化属性和更多示例见 [着色器参数传递指南](./着色器参数传递指南.md)。

## 9. 完整案例：可调灰度的纹理绘制

目标：将一个普通 `GL_TEXTURE_2D` 纹理绘制到全屏矩形，`uGrayAmount=0.0` 显示原图，`1.0` 显示灰度。先写顶点和片元代码，再配置 Android 侧数据。

**顶点着色器（GLSL ES 1.00）：**

```glsl
attribute vec4 aPosition;
attribute vec2 aTexCoord;
uniform mat4 uMvpMatrix;
varying mediump vec2 vTexCoord;

void main() {
    gl_Position = uMvpMatrix * aPosition;
    vTexCoord = aTexCoord;
}
```

**片元着色器（GLSL ES 1.00）：**

```glsl
precision mediump float;
varying mediump vec2 vTexCoord;
uniform sampler2D uTexture;
uniform float uGrayAmount;

void main() {
    vec4 sampled = texture2D(uTexture, vTexCoord);
    float luminance = dot(sampled.rgb, vec3(0.299, 0.587, 0.114));
    vec3 rgb = mix(sampled.rgb, vec3(luminance), clamp(uGrayAmount, 0.0, 1.0));
    gl_FragColor = vec4(rgb, sampled.a);
}
```

Android 侧可以沿用项目的 `GlUtil`。下例假设 `vertexSource` 和 `fragmentSource` 保存了上面的 GLSL 字符串，`textureId` 是事先创建并上传好的普通二维纹理。演示了关键 API 的完整配对：

```kotlin
import android.opengl.GLES20
import android.opengl.Matrix
import com.android.grafika.gles.GlUtil

val positions = GlUtil.createFloatBuffer(
    floatArrayOf(-1f, -1f, 1f, -1f, -1f, 1f, 1f, 1f)
)
val texCoords = GlUtil.createFloatBuffer(
    floatArrayOf(0f, 0f, 1f, 0f, 0f, 1f, 1f, 1f)
)
val mvp = FloatArray(16).also { Matrix.setIdentityM(it, 0) }

// 在当前 EGL 上下文中初始化，一般放在 onSurfaceCreated()
val program = GlUtil.createProgram(vertexSource, fragmentSource)
check(program != 0) { "着色器程序创建失败" }
val positionLoc = GLES20.glGetAttribLocation(program, "aPosition")
val texCoordLoc = GLES20.glGetAttribLocation(program, "aTexCoord")
val mvpLoc = GLES20.glGetUniformLocation(program, "uMvpMatrix")
val textureLoc = GLES20.glGetUniformLocation(program, "uTexture")
val grayLoc = GLES20.glGetUniformLocation(program, "uGrayAmount")
check(positionLoc >= 0 && texCoordLoc >= 0 && mvpLoc >= 0 && textureLoc >= 0 && grayLoc >= 0) {
    "着色器输入位置无效，请检查变量名与编译/链接日志"
}

// 在 onSurfaceChanged() 中用实际尺寸调用 glViewport(0, 0, width, height)
// 在 onDrawFrame() 中按需清屏后执行下面的绘制调用
GLES20.glUseProgram(program)
GLES20.glUniformMatrix4fv(mvpLoc, 1, false, mvp, 0)
GLES20.glUniform1f(grayLoc, grayAmount.coerceIn(0f, 1f))
GLES20.glActiveTexture(GLES20.GL_TEXTURE0)
GLES20.glBindTexture(GLES20.GL_TEXTURE_2D, textureId)
GLES20.glUniform1i(textureLoc, 0)

// 使用客户端 FloatBuffer 时，不绑定顶点 VBO
GLES20.glBindBuffer(GLES20.GL_ARRAY_BUFFER, 0)
positions.position(0)
GLES20.glVertexAttribPointer(positionLoc, 2, GLES20.GL_FLOAT, false, 0, positions)
GLES20.glEnableVertexAttribArray(positionLoc)
texCoords.position(0)
GLES20.glVertexAttribPointer(texCoordLoc, 2, GLES20.GL_FLOAT, false, 0, texCoords)
GLES20.glEnableVertexAttribArray(texCoordLoc)

GLES20.glDrawArrays(GLES20.GL_TRIANGLE_STRIP, 0, 4)
GLES20.glDisableVertexAttribArray(positionLoc)
GLES20.glDisableVertexAttribArray(texCoordLoc)
GLES20.glBindTexture(GLES20.GL_TEXTURE_2D, 0)
```

上述两个 FloatBuffer 是 direct、native-order 缓冲区，由项目工具方法创建。四个顶点与四组 UV 按相同顺序排列。将当前 `GL_TEXTURE0` 绑定的 `textureId` 传给 `sampler2D` 使用的是索引 `0`。若图像上下颠倒，应按实际纹理来源调整 UV；不要直接复制这组 UV 到所有 Bitmap、视频和 FBO 场景。`grayAmount` 若由 UI 线程更新到渲染线程，还需要按应用线程模型安全传递状态。

## 10. 迁移到 GLSL ES 3.00

在 `GLSurfaceView.setRenderer()` 之前请求 `setEGLContextClientVersion(3)`，并确认设备支持 ES 3.0。ES 3.0 上下文依然可以使用兼容的 ES 1.00 程序；只有需要 ES 3.00 语法时，才将**顶点与片元**源码都改为以 `#version 300 es` 开头。常见对应关系：

| GLSL ES 1.00 | GLSL ES 3.00 |
|---|---|
| 顶点输入 `attribute` | 顶点输入 `in`，可用 `layout(location = 0)` 固定属性位置 |
| 顶点输出/片元输入 `varying` | 顶点 `out` / 片元 `in` |
| `texture2D(uTexture, uv)` | `texture(uTexture, uv)` |
| `gl_FragColor` | 用户定义的片元 `out vec4 fragColor` |
| 常用标量/向量 | 增加 `uint`、整数输入/输出等类型与相应接口 |

**ES 3.00 顶点着色器：**

```glsl
#version 300 es
layout(location = 0) in vec4 aPosition;
layout(location = 1) in vec2 aTexCoord;
uniform mat4 uMvpMatrix;
out mediump vec2 vTexCoord;

void main() {
    gl_Position = uMvpMatrix * aPosition;
    vTexCoord = aTexCoord;
}
```

**ES 3.00 片元着色器：**

```glsl
#version 300 es
precision mediump float;
in mediump vec2 vTexCoord;
uniform sampler2D uTexture;
layout(location = 0) out vec4 fragColor;

void main() {
    fragColor = texture(uTexture, vTexCoord);
}
```

ES 3.0 还支持 VAO、UBO、实例化绘制、更多纹理/采样能力；具体功能要同时满足 GL 上下文版本、Shader 语言版本和相应 API 调用。顶点整数输入应搭配 `glVertexAttribIPointer()`；普通 `glVertexAttribPointer()` 提供的是浮点属性路径。关于 GLES30 参数传递细节，请继续阅读项目中的[着色器参数传递指南](./着色器参数传递指南.md)。

ES 3.00 的整数类型阶段间输入/输出不能按浮点值插值，应使用 `flat` 限定符，并保持两端声明匹配，例如顶点阶段 `flat out int vId;` 与片元阶段 `flat in int vId;`。

## 11. 错误排查和性能建议

| 现象 | 优先检查 |
|---|---|
| 编译失败 | `glGetShaderInfoLog()`；`#version`/`#extension` 顺序、精度声明、类型、函数是否属于当前 GLSL 版本 |
| 链接失败 | `glGetProgramInfoLog()`；顶点 `varying/out` 与片元 `varying/in` 的名称、类型、精度及数组大小 |
| 变量位置为 `-1` | 拼写、Program 是否链接成功、是否被优化掉、是否查询了另一 Program |
| 黑屏或纯色 | `glUseProgram`、viewport、顶点范围与 draw count、属性数组、纹理绑定、uniform、EGL 上下文 |
| 纹理全黑 | 纹理目标/采样器不匹配、纹理不完整、采样器索引与活动单元不一致 |
| 画面倒置或镜像 | UV 顺序、`SurfaceTexture.getTransformMatrix()`、FBO 与屏幕的坐标约定 |
| 精度条纹/抖动 | `mediump` 范围或精度是否足够；必要时查询并使用 `highp` |
| GPU 开销高 | 每片元多次纹理采样、复杂分支、循环、过多 `discard`、重复编译/切换 Program |

排查顺序建议：先用常量颜色片元着色器验证顶点与 Program，再用 UV 渐变验证顶点属性与插值，最后接入纹理和复杂滤镜。改变某个 GL 状态后可调用 `GlUtil.checkGlError()` 辅助定位，但 `glGetError()` 不能替代编译/链接日志。

性能方面，Program 和纹理应在上下文生命周期内复用；不要每帧重新编译 Shader。尽量把与顶点有关的计算放在顶点阶段，把片元阶段的大量重复采样控制在必要范围。优化应以目标设备的实际测量为依据，不能只凭源码行数判断 GPU 成本。
